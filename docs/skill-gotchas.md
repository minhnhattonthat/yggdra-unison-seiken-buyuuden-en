# Skill gotchas (one line each: reference file, then the fact)

- references/platform-nds.md (fonts/VWF): immediate-mode system text (redrawn every frame, one texture slot per glyph, slot cached by `codes[slot] == glyph`) packs into 16 px cells by replacing the queue function whole: key each cell (hash of code, font, x in cell) into the game's codes[] with a value above every game code plus a full key in a side array, so the game's own resets still invalidate it; clamp to the pool capacity (the original overran it and crashed on long lines).
- references/setup.md: `fetch_emu.py` failed on this machine (504, then SSL CERTIFICATE_VERIFY_FAILED in urllib); `gh release download qa-2 -R minhnhattonthat/desmume` works. The zip unpacks to `tools/desmume/desmume-qa/`, which emu.py still finds.
- references/pipeline.md §Recon: kanji template matching (MS Gothic / Yu Gothic, 12-16 px, bbox-normalised correlation) got only 2-9/32 right on a bold outlined 16x16 4bpp DS font; budget for reading kanji by eye from sheets.
- references/platform-nds.md: Sting's DATA.SFS keeps its directory (hash, size, sector) inside arm9.bin, not in the archive; found by searching arm9 for the sector sequence of known file starts (stride-12 u32 1,4,6,7).
- references/graphics.md §Survey: some NDS games draw all 2D UI as 3D textures (NTFT/NTFP/NTFI = texel/palette/4x4 index); BG/OBJ VRAM dumps and vramfind.py find nothing. Tell: an index part exactly half the texel part (4x4 compression). Width isn't stored; a "smoothest row joins" guess over powers of two worked for every text texture.
- references/graphics.md §Survey: unknown file extensions in a hashed archive: log every name passed to the game's open call with an on_exec Lua hook during a boot run; it named 2,967 more files here (.PACK/.BI/.LTFT).
- references/emulator-qa.md §Visual QA: `codex exec -i` as a stand-in reviewer for a dispatched worker can hit a usage limit; budget to read sheets yourself (pack all small textures into ~1600x1800 pages; 2,497 textures fit in 29 pages).
- references/emulator-qa.md §Debug tool: NDS games that swap scenes by overlay often keep a scene table in arm9; searching arm9 for runs of u32s pointing into the shared overlay load address found it here (16-byte records init/main/exit/overlay id), and its reader gave the scene manager (current/next/phase): writing next + phase from Lua is a clean warp.
- references/emulator-qa.md §Debug tool: a warp that jumps straight past the game's New Game path skips the new-game init (map unowned); drive the real menu path by taps keyed on the scene id, then jump from the first in-game scene. L.press() from L.on_frame queues touches, and L.finish() ends a run as soon as the target is reached.
- references/emulator-qa.md §Visual QA: DeSmuME models card-read timing, so moving files in an archive (identity relayout) shifts load-dependent frames: a credits warp shot landed mid-fade on one layout and finished on the other at the same frame; compare relaid builds on static scenes or hold longer.
- references/pipeline.md §Recon: two-byte glyph codes need the draw loop, not a guess: here `F1..F9, xx` = (b-0xF0)*0xF0+xx (mla #0xF0), not *0x100. The wrong stride decoded kana fine and only showed as "codes past the font end" in late files; the tutorial on screen settled it.
- references/pipeline.md §Recon: reading ~1,700 16x16 kanji by eye from 160-glyph sheets (zoom 3) worked; a janome pass (kanji never inside a dictionary word, unknown compounds) then caught ~45 look-alike misreads (選/遥, 願/顔, 賛/貿). Key readings by bitmap hash so one reading fills every font.
- references/pipeline.md §Extract: a font can hold one kanji twice; give later copies a variation selector in the table so jp shows the char and encode(decode) still round-trips (tbl.py otherwise emits raw [XX] bytes for the second code).
- references/pipeline.md §Extract: a bold/display font with no fixed kana block (Yggdra FONT_ITEM) can be read for free when the same names exist in a known font: align the two record fields char by char (221 names gave 326/330 glyphs, zero conflicts), after fixing the known font's misreads first, since they propagate.
- references/pipeline.md §Extract: FF-splitting a pool merged a 4-byte code-read data block with the string after it (no FF between them); list every pointer target that lands strictly inside a split string and check each one.
- references/platform-nds.md (ITCM free space): when the ITCM autoload block has bss, code appended to its data lands in the bss the game uses; append zeros for the bss first, put the hooks after it and set bss to 0 (ndspy MainCodeFile save is byte-exact; only the module-params words change).
- references/platform-nds.md (keystone): keystone exposes no symbol table and prefix-assembling to find a label fails on forward refs; start the blob with a `b label` jump table and BL the sites to its fixed entries; reserve tables with `.space` at the end and splice the bytes in.
- references/pipeline.md §Marker: NDS games that copy one 16x16 glyph per character into a per-scene slot pool hang when English needs more glyphs than the Japanese (Yggdra ending: 32 dialogue slots). A per-letter VWF is not enough there: pack each line into 16 px cells at runtime, and widen the quad if the game drew 12 px of each slot. Bisect a marker hang by family, then file regex, then MARKER_SAME (same byte length) vs MARKER_GROW (file growth) to tell a length limit from a moved-pointer bug.
- references/emulator-qa.md §Debug tool: warp savestates made before a code change replay the old code (ITCM + main RAM); a shot from such a state showed every dialogue cell clipped to 12 px and looked like an engine bug. emu.py warns "state older than the ROM": regenerate states before judging any render.
- references/pipeline.md §Marker: an NDS game can draw one text family glyph by glyph from overlay code with its own fixed advance (Yggdra EDMES: ov9_15 `add r4,r4,#0xB` around a one-glyph draw call), so a VWF hooked in the arm9 run/dialogue routines misses it; log the callers of the single-glyph draw (callers.lua) on every text screen.
- references/pipeline.md §Checks (jp_left): with a one-byte glyph-index encoding, `--slots` built from every aligned pointer into the data area (tools/ptrslots.py) cut 17k noise runs to one real block (help text past a pool end); group hits by 4 KB bucket and read only buckets with long runs.
- references/platform-nds.md (free RAM): OS_GetInitArenaLo (a 7-case switch returning literals: main = end of the largest overlay, ITCM = end of ITCM bss, DTCM, ...) tells where free RAM begins; a new arm9 autoload section at the main arena lo (ndspy MainCodeFile.sections.append, generic autoload table) plus raising that literal gives a resident block for relocated strings. ITCM hooks placed after the ITCM bss sit on the ITCM arena: raise that literal too.
- references/pipeline.md §Width gate: on a game whose system text draws from a few routines, a probe on their entry (x, y, font, caller, string bytes) on the marker build maps every drawn string id to its screen and position in one 35-scene warp run (tools/lua/systrace.lua + tools/sysmap.py); most system text still needs submenu tours.
- references/emulator-qa.md §Agent playtest (DeSmuME QA fork qa-2): after a savestate load the shot stays one flat grey (186,186,186) for ~125 frames while the game runs (systrace logs from frame 1); play.py's default warm 90 + --wait 30 lands inside it. Use --wait 60 or more on NDS.
- references/emulator-qa.md §Agent playtest (NDS): play.py step PNGs are 2x with a 2 px gap (514x770; bottom screen y = (png_y - 386) / 2); images shown to the agent are rescaled, so read box edges with a row scan of the PNG, never by eye off a sheet.
- references/pipeline.md §Marker: base-36 marker codes in a font whose lowercase p/q read like P/9 get misread off shots (q0 read as 90); map drawn strings by a draw-routine probe (systrace) instead of reading the code.
- references/pipeline.md §Marker: script markers left unfilled can run past a box by 2x and overrun a per-object glyph-slot budget (NDS dialogue 32 slots) into other text's slots: looks like a text-corruption bug, check the JP build on the same frame first.
- references/pipeline.md (Extract): a min-length >= 2 filter on pointer-scanned strings drops real one-glyph strings (… ・ P —) used as composite parts; sweep pointers to pool edges for runs of 1 code.
- references/emulator-qa.md §Savestates (DeSmuME QA fork, NDS): a state saved on an older build of the same ROM boots and idles fine, but the first touch that makes the game load an overlay or relocated string from the new ROM hangs the emulator itself (low CPU, no more shots, exit 124). Regen every state after each build, not only after code changes.
- references/pipeline.md §Extract (data tables): a record table found by a stride scan can start earlier than its first clean-looking record when record 0's leading header bytes overlap the tail of the string before it; check the pointer fields one stride back too (4 FONT_ITEM item names were decoded with the system table as kana noise).
- scripts/lua/desmume_lib.lua (L.on_exec): DeSmuME memory.registerexec keeps one callback per address, so two --script probes hooking the same address silently drop the first (systrace on 0x020130AC killed another probe's hook). And memory.setregister("arm9.r15") inside an exec hook does not redirect execution: to call a game function, patch the BL word in RAM for one call (writedword) and restore it at the next instruction.
- emulator-qa/translation (Claude Code): the Edit tool strips trailing spaces from a line, so composite pieces ending in a space lost it ("All theMilanor's"); tools/setval.py sets one .out.tsv value exactly.
- references/emulator-qa.md (NDS, this repo's tools/lua/spmes.lua + tips.lua): a 10-frame tap through the patched CAUTION call starts the tip task once per frame, so TIP=1..3 shots show several tips overlaid; only TIP=0 / a single-frame tap gives one clean popup.
- references/emulator-qa.md (play.py, NDS): work/states/faction_select.dst from regen ignored every touch for 6 steps; reaching faction select from title.dst (new game, tap through the opening) works.
references/graphics.md: NDS 3D-texture games (no tiles/VRAM): keep the original palette and re-encode 4x4 blocks by searching (palette offset, mode) over it; avoids a palette-size change and round-trips pixel-exact (tools/gfx.py).
- references/graphics.md: a texture can be drawn partly off screen (TM_M at screen x = texture x - 33): centring English in the texture clipped it; check the on-screen frame and align to the original's visible start.
- references/graphics.md: text on a panel (EPI_WAKU0 pill): clearing the label box to transparent punches a hole; repaint rows from the panel instead (gen_gfx clear=row).
- references/graphics.md: NDS 3D UI atlases have no layout file: hook the game's 2D quad routine and log (texture name, texcoords) per scene to get each label's real UV rect (here tools/lua/quads.lua); ink segmentation can't split tightly packed labels, and a texture's whole width may not be shown (OP_WR strips 192 of 256, epilogue frame window).
- references/graphics.md: a title/logo ruby or subtitle drawn over art can't be cleared to transparent or row-repainted; blending each column between the rows above and below the box hides it cleanly (gen_gfx clear=vert); dark text on a light ribbon needs an explicit fill colour (the brightest-colour default picks the ribbon).
- references/graphics.md: clear=vert streaks when the rows above/below the box cross outlines or busy art (logo ruby over a face); a Laplace fill from the whole box border (gen_gfx clear=fill, numpy, 400 passes) hides it as a soft blur.
- references/platform-nds.md: archives keyed by name hash (DATA.SFS) hold files whose names are built at runtime and never appear as strings; give them a hash-derived pseudo-name (_unk_<hash>) that the hash function maps back, so the texture/insert pipeline handles them like named files.
- scripts/sheet.py (emulator-qa.md §Reading screenshots): a multi-tile page fits 2000 px and draws a frame inset, so pixel coordinates read off it are off by up to 30%; read box coordinates from a single-file `--crop .. --zoom N` output (texture px = image px / N, origin 0) or an ink-rect script, never from a contact sheet.
- references/graphics.md: text on a flat panel crossed by leader lines (labelled diagrams): row-repaint (clear=row) drags each line through the box as a streak; paint the commonest border colour instead (gen_gfx clear=panel) and keep the boxes tight to the original ink so the lines stay.
- references/emulator-qa.md §Visual QA: a cold-boot tour needs no savestates per ROM: give the warp script a TOUR route played once the scene is reached (shots every N frames, finish when the route ends), so the same list tours the English build and the original (tools/debug/tour.txt, warp.lua TOUR/EVERY).
- references/emulator-qa.md §Text coverage: when strings live in RAM buffers (script files loaded per event) and a relocated block, key coverage by content: hash the bytes before the terminator at each draw entry (Lua, no bit ops: h = (h*31 + b + 1) mod 4294967291) and write the same hash per id from the build's encoded strings (tools/lua/textcover.lua + tools/cover.py).
- references/emulator-qa.md §Visual QA: codex exec can hit its usage limit mid-project (Orca worker with no subagents): the read-only verdict pass then falls back to the main agent's own context, ~1.5k tokens per 1024x768 sheet, so plan ~80 sheets per fresh worker.
- emulator-qa.md: inkbox.py takes the rect's commonest colour as background, so on gradient buttons it reports nonsense margins; measure the text fill (white pixels) instead and compare with the original's frame (tools/inkx.py here).
- references/emulator-qa.md §Visual QA / platform-nds.md: NDS games that show 3D on both screens alternate engine A each frame and show the other screen as a display capture (sub BG2 direct-colour bitmap or 12 bitmap OBJs): a quad-draw hook (tools/lua/quads.lua) sees only one draw path, and VRAM probes must dump both frame parities (tools/lua/ppuevery.lua, texvram.lua: maps banks A-D to LCDC for one read; tools/oamlist.py lists OBJs).
- references/graphics.md §Lettering: atlas rows packed with no gap: a box that is a few px too wide clears a neighbour's strokes (here SYSTEX army-name boxes ate the V/A of the VIT/ATK stat block); clip every box to the original's ink extent of that one label and check the neighbours on screen.
- references/graphics.md §Lettering: the game's UV rects of packed atlas rows overlap by 1-3 px, so an English label's descenders (y, p, g) show as dashes above the next row's label on screen (SYSTEX Move Type over Weakness); pick descender-free wording or a shorter box for a label with a row right below it.
- references/platform-nds.md / translation.md: a game's own lowercase Latin glyphs may be drawn raised with no descender (p q g with the bowl above x-height, read as P / 9: "uPon", "amon9"); look for that on the glyph torture line and shift them down to the baseline when the cell has 2 rows below it (tools/enfont.py DROP).
- references/emulator-qa.md §Visual QA: a tour run with 6 parallel DeSmuME jobs (regen.py --jobs 6) gives dark horizontal bands / black strips at fixed screen rows on fade-heavy scenes (epilogue, credits, battle) that the original's tour lacks; rerun the case alone (--jobs 1) before calling it a bug: here the isolated run was clean (row-luminance profile identical to the original).
- references/emulator-qa.md §Text coverage / platform-nds.md: DeSmuME Lua memory.readdword on an unaligned address reads the aligned word below it (ARM semantics): read script operands byte-wise. For bytecode script games, drive the game's own interpreter (hook its dispatch loop, queue every switch target, start the script once per block) instead of playing: 7,900 MESSAGE strings here in ~10 min of 3 parallel runs (tools/lua/msgall.lua, tools/msgcover.py); chaining blocks inside one event leaked text objects and hung after ~38 lines. A savestate older than the ROM can silently ignore a patched-call trick: regen it first.
- references/emulator-qa.md §Text coverage: event scripts that need a live context (duel portraits / unit ops here) can freeze the game when forced outside it; load the file through a simpler script task and turn every non-text opcode into the interpreter's own 1-byte no-op in RAM, with each wait-for-page op made an end op and each line queued as its own start (tools/lua/msgall.lua duelnop: 3,282 SPMES lines in ~20 min). A file-name swap hook must stay on for the whole run: the loader opens the file more than once.
- references/emulator-qa.md §Text coverage / platform-nds.md: DeSmuME QA fork exec hooks (L.on_exec) under JIT never fired on a short block that is only a branch target (ov9_15 0x0211D280-88 here; the beq before it fired, --debugger did not help other missed draws): when a register override seems ignored, log a hit on each instruction of the path and hook the branch instead. A savestate from an older build can crash (0xC0000005) as soon as the scene loads new code: regen it on the current ROM.
- references/emulator-qa.md §Text coverage / platform-nds.md: DeSmuME QA fork under JIT also never fired an exec hook on the instruction right after a BL (a call-return address: ov9_05 0x0211B930) nor on the small getter it called; to force a check result, write the flag the getter returns (loadfail.lua) instead of the register. Fault injection (save result forced to -1, load flag cleared) is how the "Failed to save / load" bands get coverage without a broken card.
- references/emulator-qa.md §Text coverage: a content-hash coverage key (strings copied to RAM buffers) never matches a template the game writes digits into before each draw ("000:" here): waive it with the writing instruction as proof. Catalog grid taps from a fitted formula can skip a whole row and hit the next one twice (the 45 + 24.3r item grid missed row 4 on every page, 113 strings): when coverage holes form a stride pattern, re-shoot one cell of the hole and read which cell it opened.
